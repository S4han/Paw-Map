## 1. 제품 정의

| 항목 | 내용 |
|---|---|
| 제품명 | PAW MAP (가칭) |
| 한 줄 정의 | 현재 위치 또는 목적지 주변의 반려견 동반 음식점·카페·숙소·관광지를 통합 검색하고, **내 반려견 조건(몸무게·마릿수·실내 필수)으로 실제 이용 가능 여부를 근거와 함께 판단**해 주는 모바일 우선 PWA |

| 서비스 범위 | 전국 검색 가능한 구조. 초기 검증 지역은 **제주**(사용자 결정, 2026-10-13). 단 STEP 2에서 제주의 API 데이터 양이 부족하면 대체 지역을 제안한다 |
| 운영비 목표 | 월 0원 (보장하지 않음. §9 검증 항목으로 판단) |
| MVP 제외 | 회원가입·로그인, 예약·결제, 실시간 객실 조회, 리뷰·평점, 서버에 사용자 위치·프로필 저장 |

### 1.1 제품 원칙

1. **모르는 것은 모른다고 표시한다.** 제공되지 않은 값(`undefined`)을 `true`/`false`로 바꾸지 않는다. 조건을 알 수 없는 장소는 "적합"으로 표시하지 않는다.
2. **모든 동반 정보에는 근거가 있다.** 출처, 근거 유형, 확인일을 함께 보여준다.
3. **충돌은 확정하지 않는다.** 출처끼리 다르면 양쪽을 다 보여주고 "확인 필요"로 둔다.
4. **경쟁 서비스에 대해 확인 없이 주장하지 않는다.** (반려생활, 하트독, 펫츠고 등은 벤치마킹 대상일 뿐, "이 기능이 없다" 같은 문구는 쓰지 않는다)
5. **공식 목록에 있다는 것이 현재 동반 허용이나 실내 입장을 보장하지 않는다.** 화면에 상시 고지한다.

## 3. 사용자 스토리와 MVP 수용 기준

우선순위는 마스터 지침과 같다(P0 = MVP 필수, P1 = MVP 이후 1순위, P2 = 2차).

### US-01 반려견 프로필 조건 검색 (P0)

> 12kg 반려견 2마리와 실내에 함께 들어갈 수 있는 곳을 찾고 싶다.

- AC-01-1 몸무게(kg)·마릿수·실내 필수를 입력하면 결과 카드마다 `조건 적합` / `조건 불일치` / `확인 필요` 중 하나가 표시된다.
- AC-01-2 프로필을 비워두면 매칭 배지는 표시되지 않고 동반 상태(`가능`/`불가`/`미확인`)만 표시된다.
- AC-01-3 조건 정보가 없는 장소는 절대 `조건 적합`이 되지 않는다(§6 규칙 단위 테스트로 검증).
- AC-01-4 프로필은 이 기기 브라우저에만 저장되고, 새로고침 후에도 유지된다. 서버로는 검색 요청 시 매칭에 필요한 값만 보내거나, 매칭을 브라우저에서 수행한다(STEP 3 결정).
- AC-01-5 카드의 `확인 필요`를 누르면 어떤 조건이 왜 확인되지 않았는지 보인다(예: "최대 마릿수 정보 없음").

### US-02 근거 있는 동반 상태 (P0)

> 이 정보를 믿어도 되는지, 언제 누가 확인한 정보인지 알고 싶다.

- AC-02-1 모든 장소 카드에 동반 상태, 대표 출처, 확인일(또는 "확인일 정보 없음")이 표시된다.
- AC-02-2 상세 화면에 출처별 근거(출처명, 근거 유형, 확인일, 원문 요약, 출처 링크)가 모두 나열된다.
- AC-02-3 출처끼리 동반 여부가 다르면 `미확인` + "출처 간 정보 충돌" 표시, 양쪽 근거를 함께 보여준다.
- AC-02-4 "방문 전 업체에 확인하세요" 고지가 상세 화면에 항상 있고, 전화번호가 있으면 바로 전화할 수 있다.

### US-03 4개 카테고리 통합 검색 (P0)

> 카페와 음식점을 한 번에, 반경을 바꿔가며 보고 싶다.

- AC-03-1 카테고리: 음식점·카페·숙소·관광지. 복수 선택 가능, 기본은 전체 선택.
- AC-03-2 반경: 1·3·5·10km, 기본 3km.
- AC-03-3 반경 밖 장소는 서버에서 실제 좌표 거리(하버사인)로 다시 걸러 표시하지 않는다.
- AC-03-4 결과 수가 출처 API 상한에 걸리면 "일부만 표시됨, 지도를 확대해 다시 검색" 안내.

### US-04 지도 + 목록 연동 (P0)

> 지도에서 위치를 보며 목록에서 고르고 싶다.

- AC-04-1 현재 위치 버튼: 권한 허용 시 내 위치로 이동 후 검색. 거부 시 기본 지역(제주) 지도 + 지역 검색 안내, 다른 기능은 모두 사용 가능.
- AC-04-1a (2026-10-13 사용자 요청) 앱을 열면 현재 위치를 자동으로 요청해 기준점으로 쓴다. 확인 전·실패 시 기본 위치(제주시청) + 안내. 위치를 받기 전에 사용자가 지역 검색·"이 지역 검색"으로 옮겼으면 덮어쓰지 않는다.
- AC-04-2 지역명·주소·관광지명 검색 → 후보 선택 → 그 지점 중심으로 검색.
- AC-04-3 지도를 움직이면 "이 지역 검색" 버튼이 나타나며, **자동 재검색은 하지 않는다**(비용).
- AC-04-4 목록은 거리순, 목록 항목 ↔ 지도 마커 선택이 서로 강조된다. 마커가 겹치면 묶어서 표시.

### US-05 상세 정보 (P0 — 기본 정보 / P1 — 숙소 특화)

- AC-05-1 이름, 업종, 주소(복사), 전화(`tel:`), 위치, 영업시간(제공 시), 반려견 제한사항 전체, 근거 목록.
- AC-05-2 외부 길찾기: 카카오맵·네이버지도 링크(형식은 STEP 2 검증).
- AC-05-3 숙소는 예약 사이트로 **링크만** 제공하고, 예약 가능 여부·객실 재고를 주장하지 않는다.

### P1·P2 (MVP 이후, 별도 승인)

| 우선순위 | 기능 | 요구사항 요약 |
|---|---|---|
| P1 | 상세 조건 필터 | 실내/실외, 이동장, 목줄, 크기, 추가 요금, 최대 마릿수 |
| P1 | 숙소 특화 | 반려견 추가 요금, 운동장, 개별 울타리, 숙소 유형(호텔·펜션·리조트·풀빌라·캠핑·글램핑) |
| P1 | 정보 변경 제보 | 제보는 `USER_REPORT`로 별도 보관, 관리자 확인 전에는 판정에 반영하지 않음 → 저장소 필요(D1 검토) |
| P2 | 신뢰도·신선도 | 근거 유형별 구분 표시, 오래된 정보 재확인 유도 |
| P2 | 반려견 여행 코스 | 동반 가능 장소 조합 추천 |

#### STEP 10 결정 (2026-10-14, 사용자 선택: 서버 없이 되는 기능 먼저)

| 기능 | 이번 범위 | 규칙 |
|---|---|---|
| 즐겨찾기 | ✅ | 이 기기 브라우저(`localStorage` `pawmap.favorites.v1`)에만 저장, 서버 전송 없음. 이름·카테고리를 같이 저장해 데이터에서 빠져도 목록에 이름은 남김. 반경·필터와 상관없이 "저장한 곳"에서 모아 봄 |
| 데이터 신선도 | ✅ | 기준은 출처 확인일(`lastVerifiedAt`)뿐, 조회 시각은 쓰지 않음. 1년 이상 "1년 넘은 정보", 2년 이상 "N년 넘은 정보" + 재확인 안내. 날짜 없음은 "오래됨"이 아니라 "확인일 정보 없음"으로 따로 안내. 출처 자동 우선순위는 여전히 도입하지 않음(§7.3) |
| 여행 코스 | ✅ | 기준점에서 관광지 → 음식점 → 카페 순, 각 단계에서 앞 장소와 가장 가까운 **동반 가능(ALLOWED)** 장소. 반려견 조건이 있으면 "조건 불일치" 제외, "확인 필요"는 표시하고 포함. 10km 넘게 떨어지면 그 단계는 빼고 알림. 직선거리 기준(경로·영업시간 미반영)을 화면에 명시 |
| 정보 수정 제보 | ✅ 임시 | 상세 화면에서 장소 정보를 채운 GitHub 이슈 작성 화면으로 연결(서버·비용 없음, GitHub 계정 필요, 공개됨). 판정에 바로 반영하지 않고 다음 데이터 갱신 때 사람이 확인(`USER_REPORT` 원칙). 사용자 위치·반려견 조건은 넣지 않음 |
| 관리자 검증·앱 내 제보 저장 | ❌ 다음 단계 | 저장소(D1 등)·스팸·개인정보 설계와 리소스 생성 승인 필요 |

## 5. 반려견 프로필 입력 UX

### 5.1 입력 항목

| 항목 | 타입 | 입력 방식 | 범위·검증 | 비워두면 |
|---|---|---|---|---|
| 몸무게 | `weightKg?: number` | 숫자 입력(키패드 `decimal`), 단위 kg 고정 표시 | 0.5 ~ 100, 소수 1자리 | 크기 조건 평가 안 함 |
| 마릿수 | `dogCount?: number` | − / + 스테퍼 | 1 ~ 5 | 마릿수 조건 평가 안 함 |
| 실내 필수 | `indoorRequired?: boolean` | 토글 스위치 "실내에 함께 들어가야 해요" | on/off | off = 평가 안 함 |

- **여러 마리의 몸무게가 다를 때:** MVP는 몸무게 입력 칸 하나에 **가장 무거운 아이의 몸무게**를 넣도록 안내 문구를 붙인다(확인 필요 사항 Q-1).
- 견종 입력은 MVP 제외(견종별 제한은 P1 필터).

### 5.2 화면 흐름

1. 메인 상단 검색 조건 줄에 **[🐕 내 반려견]** 칩. 미설정 시 "조건 설정", 설정 시 "12kg · 2마리 · 실내" 요약 표시.
2. 칩을 누르면 하단 시트(조건 패널)가 열린다. 3개 항목 + [적용] [초기화].
3. 첫 방문 시 한 번만 "반려견 조건을 설정하면 갈 수 있는 곳을 골라드려요" 안내(닫으면 다시 안 띄움).
4. 적용하면 **API 재호출 없이** 현재 결과의 매칭 배지만 다시 계산한다(비용).
5. 저장: `localStorage`(`pawmap.profile.v1`). 저장 실패(사생활 보호 모드 등) 시에도 이번 세션 동안은 동작한다.

## 6. 상태 분류 규칙

### 6.1 두 가지 상태의 차이

| 구분 | `PetStatus` | `MatchStatus` |
|---|---|---|
| 질문 | "이 장소는 반려견 동반을 허용하는가?" | "**내 반려견 조건으로** 이 장소를 이용할 수 있는가?" |
| 값 | `ALLOWED` 가능 / `NOT_ALLOWED` 불가 / `UNKNOWN` 미확인 | `MATCH` 조건 적합 / `MISMATCH` 조건 불일치 / `NEEDS_CONFIRMATION` 확인 필요 |
| 결정 요소 | 장소의 근거(evidence)만 | `PetStatus` + 장소의 `PetConditions` + 사용자 `PetProfile` |
| 프로필 없을 때 | 항상 계산 | 계산하지 않음(표시 안 함) |
| 화면 표기 | ✅ 동반 가능 / 🚫 동반 불가 / ❔ 미확인 (아이콘+글자, 색만으로 구분 금지) | 🟢 조건 적합 / 🔴 조건 불일치 / 🟡 확인 필요 (아이콘+글자) |

### 6.2 `PetStatus` 결정 규칙

1. 동반 여부 근거가 하나도 없다 → `UNKNOWN`
2. 근거가 모두 같은 값 → 그 값
3. 근거가 서로 다르다 → `UNKNOWN` + `conflictingEvidence = true` (자동으로 한쪽을 고르지 않음)
4. 관리자 확인 전 `USER_REPORT`는 판정에 쓰지 않고 상세에만 "제보됨(미확인)"으로 표시(P1)

### 6.3 `MatchStatus` 결정 규칙 (프로필이 있을 때)

평가 대상 조건 = 사용자가 프로필에 **입력한 항목**만.

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | `PetStatus = NOT_ALLOWED` | `MISMATCH` |
| 2 | `PetStatus = UNKNOWN` | `NEEDS_CONFIRMATION` |
| 3 | 평가 대상 중 하나라도 **확인된 값으로 명시적 불충족** | `MISMATCH` |
| 4 | 평가 대상 중 하나라도 **값 없음 또는 출처 간 충돌** | `NEEDS_CONFIRMATION` |
| 5 | 평가 대상이 모두 확인되어 충족 | `MATCH` |

조건별 판정(`undefined`는 언제나 "값 없음"):

| 프로필 항목 | 충족 | 명시적 불충족 | 값 없음 |
|---|---|---|---|
| `weightKg` | `minWeightKg ≤ weightKg ≤ maxWeightKg` (있는 경계만 비교, 양쪽 다 없으면 값 없음) | 범위를 벗어남 | `min/maxWeightKg` 둘 다 없음 |
| `dogCount` | `dogCount ≤ maxDogs`, 또는 `dogCount = 1`이고 `PetStatus = ALLOWED`(Q-2) | `dogCount > maxDogs` | `dogCount ≥ 2`이고 `maxDogs` 없음 |
| `indoorRequired = true` | `indoorAllowed = true` | `indoorAllowed = false` | `indoorAllowed` 없음 |

경계값 규칙: "5kg 이하" → `maxWeightKg = 5`, 5.0kg은 충족. "5kg 미만"은 `maxWeightKg = 4.9`로 바꾸지 않고 별도 플래그(`maxWeightExclusive`)로 보관 — STEP 7에서 모델 확정.

**출처 원문을 숫자로 바꾸는 규칙**
- "5kg 이하"처럼 kg 숫자가 명시된 경우만 `maxWeightKg`로 변환한다.
- "전 견종 동반 가능"은 **몸무게 제한이 없다고 명시된 것**으로 보고 몸무게 조건을 충족 처리한다(D-7, 값 없음과 구분).
- "소형견만", "중형견 이하"처럼 kg 기준이 없는 표현은 **kg으로 추정하지 않는다** → `notes`에 원문 보관, `weightKg` 평가는 "값 없음" → `NEEDS_CONFIRMATION`.
- `allowsDogs = true`(Google)는 `PetStatus` 근거로만 쓰고, 실내 허용·크기·마릿수를 추정하지 않는다.
- 관광공사 `acmpyTypeCd = 전구역 동반가능`은 **실내 공간이 있는 업소(음식점·카페·숙소·문화시설)에 한해 `indoorAllowed = true`** 로 본다(D-7). 야외 관광지는 실내 판정 대상이 아니다.
- "일부구역 동반가능"은 `ALLOWED`로 보되 `indoorAllowed`는 값 없음으로 둔다.

**예시** (프로필: 12kg · 2마리 · 실내 필수)

| 장소 조건 | 결과 | 사유 표시 |
|---|---|---|
| 동반 가능, 최대 15kg, 최대 2마리, 실내 가능 | 🟢 조건 적합 | — |
| 동반 가능, 10kg 이하 | 🔴 조건 불일치 | 몸무게 제한 10kg 이하 |
| 동반 가능, 실외(테라스)만 | 🔴 조건 불일치 | 실내 동반 불가 |
| 동반 가능, 소형견만 | 🟡 확인 필요 | 몸무게 기준(kg) 정보 없음 |
| 동반 가능, 그 외 정보 없음 | 🟡 확인 필요 | 몸무게·마릿수·실내 정보 없음 |
| 출처 A 가능 / 출처 B 불가 | 🟡 확인 필요 | 출처 간 정보 충돌 |
| 동반 불가 | 🔴 조건 불일치 | 반려견 동반 불가 |

### 6.4 목록 필터와의 관계

- 동반 상태 필터(기본 **"동반 가능만"**, 사용자 결정): `동반 가능만` / `미확인 포함` / `전체`.
- 프로필이 있으면 매칭 필터 칩 추가: `전체` (기본) / `조건 적합` / `확인 필요` / `불일치`. 각 칩에 개수 표시.
- 정렬은 거리순 고정(MVP). 매칭 상태로 숨기거나 순서를 바꾸지 않아 "적합만 보여서 놓치는" 일을 막는다.

## 7. 정보 출처·확인일·충돌 처리

### 7.1 근거 유형

| `EvidenceType` | 의미 | MVP 사용 |
|---|---|---|
| `OFFICIAL` | 공공기관 공식 데이터(한국관광공사, 식약처 등) | ✅ |
| `PROVIDER` | 민간 플랫폼 데이터(Google Places 등) | ✅ (STEP 2 결과에 따라) |
| `BUSINESS_CONFIRMED` | 업체가 직접 확인해 준 정보 | P2 |
| `USER_REPORT` | 사용자 제보(관리자 확인 전) | P1 |

### 7.2 확인일

| 필드 | 정의 |
|---|---|
| `Evidence.checkedAt` | 그 출처가 해당 정보를 **확인·수정했다고 제공한 날짜**. 출처가 날짜를 주지 않으면 비워둔다 |
| 조회 시각 | 우리가 API를 호출한 시각. `checkedAt`에 넣지 않는다(확인일로 오인 방지). 화면에는 "조회 2026-10-13"처럼 다른 문구로 표시 |
| `PetPlace.lastVerifiedAt` | `OFFICIAL`·`BUSINESS_CONFIRMED` 근거의 `checkedAt` 중 가장 최근 값. 없으면 비움 → 화면 "확인일 정보 없음" |

### 7.3 충돌 처리

- 충돌 단위: 동반 여부(`PetStatus`)와 조건 필드(`indoorAllowed`, `maxWeightKg`, `maxDogs` 등) 각각.
- 동반 여부 충돌 → §6.2 규칙 3. 조건 필드 충돌 → 해당 조건은 "값 없음"과 같이 취급(`NEEDS_CONFIRMATION`), 상세에 출처별 값을 나란히 표시.
- MVP에서는 최신 날짜나 출처 등급으로 자동 우선 적용하지 않는다. 근거 우선순위 규칙은 P2(신뢰도·신선도)에서 별도 승인 후 도입.

### 7.4 중복 제거

1. 출처 간 ID 매핑이 있으면 우선 사용.
2. 없으면 후보 매칭: 좌표 거리 ≤ 50m(임계값은 테스트로 조정) **그리고** 정규화 전화번호·도로명 주소·정규화 명칭 중 하나 이상 일치.
3. 이름이 비슷하다는 것만으로는 병합하지 않는다. 애매하면 별개 장소로 둔다.

## 10. 데이터 모델 (마스터 지침 초안 + 제안)

마스터 지침의 모델을 그대로 쓰고, 아래 추가를 **제안**한다(STEP 3에서 확정).

| 제안 | 이유 |
|---|---|
| `PetConditions` 각 필드의 출처별 값 보관(예: `fieldEvidence`) | 조건 필드 충돌(§7.3)을 판정하려면 필드별로 어느 출처가 무엇을 말했는지 알아야 함 |
| `maxWeightExclusive?: boolean` | "이하"와 "미만" 구분(§6.3 경계값) |
| `MatchResult { status, reasons: { field, result, message }[] }` | 카드의 사유 표시·상세의 "내 반려견 기준" 섹션(AC-01-5) |
| `Evidence.fetchedAt` | 조회 시각을 `checkedAt`과 분리(§7.2) |
| `notes?: string` → `notes?: string[]` | 출처별 원문을 여러 개 보관 |

## 11. 결정 사항

| # | 질문 | 결정 (2026-10-13 사용자 확정) |
|---|---|---|
| Q-1 | 여러 마리의 몸무게가 다를 때 | 가장 무거운 아이 몸무게 하나만 입력(안내 문구 표시) |
| D-6 | 초기 검증 지역 | **제주 유지**(현장 검증 용이). 숙소는 어느 지역이든 출처 부족 |
| D-7 | 파싱 규칙 | "전 견종 동반 가능" → 몸무게 충족 / "전구역 동반가능" → 실내 공간이 있는 업소는 실내 가능 |
| Q-2 | 마릿수 1마리일 때 `maxDogs` 정보가 없으면? | **`PetStatus = ALLOWED`이면 최소 1마리 허용으로 보고 충족 처리**, 2마리 이상일 때만 `maxDogs`가 필요. "값 없음을 허용으로 보지 않는다" 원칙의 **유일한 승인된 예외**이며, 근거는 '동반 가능'이라는 확인된 사실 자체다 |
